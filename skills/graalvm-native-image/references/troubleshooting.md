# Troubleshooting a native build or binary

Read the row whose symptom matches, then confirm with the "distinguish" column before
changing anything: several of these look identical from the stack trace alone.

## The build

| Symptom                                                                    | Likely cause                                                     | How to distinguish                                                               | Remediation                                                                                       |
| -------------------------------------------------------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Build "succeeds" but the binary starts slowly and RSS looks like a JVM     | Fallback image: the analysis gave up and embedded a JVM          | Build output names a fallback image; `--no-fallback` turns it into a build error | Fix the reported closed-world violation; keep `--no-fallback` permanently                         |
| Build fails naming a class "initialized at build time" that should not be  | A build-time-initialised class reached one marked for run time   | `-H:+PrintClassInitialization` shows who requested build-time initialisation     | `--initialize-at-run-time=<class>` for the offender, or stop the package-level build-time request |
| Build fails on `--gc=G1` or `--pgo`                                        | Community Edition, or a non-Linux host for G1                    | `native-image --version` names the distribution                                  | Oracle GraalVM on Linux x64/AArch64, or drop the feature                                          |
| CI build step dies with exit 137 and no `native-image` error               | The builder JVM was OOM-killed                                   | Container memory limit versus the builder's default heap                         | More memory for the build step; `-J-Xmx` explicit; `--parallelism` lower                          |
| `-H:` option copied from a post has no effect or fails                     | Undocumented, removed, or never a public option                  | `native-image --help-extra \| grep -i <term>`                                    | Use the documented `--` option or drop it                                                         |
| "Unsupported features" error naming `Unsafe`, a `MethodHandle` or a lambda | A library uses something the closed-world analysis cannot follow | The error names the class and the reachability path                              | Published metadata for that library, a substitution, or a different library                       |

## The binary will not start

| Symptom                                                                 | Likely cause                                                                 | How to distinguish                                                        | Remediation                                                                               |
| ----------------------------------------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Exits immediately reporting CPU features the machine lacks              | Built for `x86-64-v3` (the default) or `-march=native` on a newer build host | Compare `-march=list` with the deployment CPU                             | Rebuild with `-march=compatibility`                                                       |
| Fails before `main` with a value from the CI environment in the message | Static state snapshotted at build time                                       | `-H:+PrintClassInitialization` shows the class was build-time initialised | Lazy initialisation, `--initialize-at-run-time`, or a `@RecomputeFieldValue` substitution |
| `UnsatisfiedLinkError` for a JNI library that works on the JVM          | JNI metadata missing, or the library absent from the image's environment     | `--exact-reachability-metadata` turns the first into a registration error | Register the JNI types; ship the library alongside the binary or link statically          |

## Run-time failures the JVM never showed

| Symptom                                                                     | Likely cause                                                        | How to distinguish                                                                                            | Remediation                                                                                       |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `ClassNotFoundException` / `NoSuchMethodException` / `NoSuchFieldException` | Reflection over a non-constant name with no metadata entry          | Rebuild with `--exact-reachability-metadata`: a registration gap becomes `MissingReflectionRegistrationError` | Agent run covering that path (`config-merge-dir`), or a manual `reachability-metadata.json` entry |
| `getResourceAsStream` returns `null`                                        | Resource not registered — the most commonly forgotten metadata kind | Exact mode raises the resource variant of the missing-registration error                                      | `resources` entry with a `glob`                                                                   |
| Dynamic proxy or serialisation fails only in the binary                     | Proxy interface list or serialisable type not registered            | Exact mode                                                                                                    | `reflection` entry with `"type": {"proxy": [...]}` or `"serializable": true`                      |
| Config or feature-flag value is stale and matches the build machine         | Build-time initialisation captured it                               | The value changes with a rebuild, not with a restart                                                          | Move the read to run time (see closed-world-and-metadata.md)                                      |
| `-XX:StartFlightRecording`, heap dump or JMX "unrecognised" at run time     | Built without `--enable-monitoring`                                 | The option is missing, not failing                                                                            | Rebuild with `--enable-monitoring=jfr,heapdump,...`                                               |
| Works in the JVM test suite, fails in the binary on an untested path        | Agent coverage gap                                                  | Compare the exercised endpoints with the failing one                                                          | Run the integration suite under the agent; keep a rollback to the JVM                             |

## Measurements that look wrong

| Symptom                                      | Likely cause                                                                                    | Remediation                                                                                         |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Native RSS keeps growing for hours, no leak  | Serial GC's default ceiling is 80% of physical memory; it is filling, not leaking               | `-Xmx` on the binary, or `-R:MaxHeapSize` at build time; compare against a JVM with the same `-Xmx` |
| Native throughput "wins" in a 60-second test | The JVM had not finished warming up                                                             | Sustain load until the JVM's compilation rate plateaus, then compare (jit-compilation)              |
| PGO "made no difference"                     | Profile from a workload that missed the hot paths, or compared across two different base builds | Same base build with and without `--pgo`; profile the real traffic shape                            |
| Native startup "slower than expected"        | Measuring time-to-port-open while a framework does at run time what could be done at build time | Time to first good response on both sides; confirm the framework's own AOT processing ran           |
