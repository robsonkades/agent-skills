The repair is confined to RetryEngine.java and retains the public signature and Java 17 API baseline.

The original loop generated a new intent ID on every attempt, ignored existing terminal/UNKNOWN state, converted unresolved effects into rejection, admitted calls without checking the remaining budget, used the smaller delay, and retained replies while sleeping. These behaviors violated the supplied component contract.

The repaired engine returns existing APPLIED/REJECTED snapshots unchanged. Every dispatched attempt uses the original immutable intent and configured attempt timeout. An authoritative OK is the only new APPLIED transition and its receipt is preserved. UNKNOWN is persisted before any further admission decision. Because the supplied Contract.REPLAY_SAFE is false and no reconciliation port exists, an initially or newly unknown operation stops without automatic redispatch. Known TRANSIENT outcomes still retry when count, time, cancellation and token admission allow it. PERMANENT and other normal stops become REJECTED only without unresolved effects.

Replies are closed once with try-with-resources before persistence decisions, retry admission, sleep or normal return. Interrupted dispatch persists UNKNOWN and propagates InterruptedException. Pre-interruption and interruption after sleep prevent another call; interruption is not converted into a successful or rejected return. Cancellation is checked before dispatch and around backoff.

Admission uses comparison and subtraction instead of adding durations, so attempt, reserve and wait arithmetic cannot overflow. Each retry waits max(localWaitNanos, serverMinimumNanos), requires space for the full delay plus attempt and reserve, and obtains one token. The initial call needs no token. After sleeping the engine rechecks time and cancellation; an oversleep can consume a grant without authorizing a call. The chosen local delay is preserved without adding randomness.

Validation used the actual output implementation through the inspected runner: node run.mjs Verification compiled with javac --release 17 and passed 29 named scenarios; node run.mjs Smoke passed. The verification covers stable identity/payload and timeout propagation, permitted retries, UNKNOWN across a second invocation, terminal replay, exact/insufficient/overflowing budgets, server/local minimum delays, attempt exhaustion, denied tokens, cancellation, interrupted dispatch/sleep and reply ownership. A BigInteger test oracle checks budget admission independently of the implementation's subtraction. All seven immutable project copies matched their inputs by SHA-256. Installed Java and javac reported 25.0.3; every Java subprocess had the runner's or version probe's 20-second timeout.

These are deterministic authored simulations. The store's durability and atomicity are supplied assumptions, not established by the in-memory fixture. There is no database/isolation, framework, provider endpoint/version, transport cancellation or recovery implementation to validate. The fixed false replay-safety contract is exercised; no alternate true contract was substituted. No result establishes physical cancellation, production latency, fleet amplification or a provider's replay/retention guarantee. A real integration would need contract-specific outcome classification, durable recovery and fault tests across dispatch/acknowledgement loss.

The supplied idempotency, timeouts-and-deadlines, retries-and-backoff skills and their six local references informed the repair. References to other skills and external providers were not followed: only the supplied snapshots were available/authorized, and browsing was forbidden.
