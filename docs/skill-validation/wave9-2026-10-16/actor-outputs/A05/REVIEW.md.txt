# RetryEngine repair

The original runner changed the intent ID on every call, discarded earlier uncertainty, ignored terminal stored results and total-budget admission, chose the smaller delay, and retained replies across sleep. Budget refusal and interruption could also leak a reply.

The repair retains the public signature and Java 17 API baseline. It forwards the original immutable intent and configured attempt timeout. Stored APPLIED/REJECTED results return unchanged with zero calls. Initial or observed UNKNOWN survives every non-OK response and normal stop; only authoritative OK records APPLIED and its receipt. An InterruptedException during dispatch persists UNKNOWN before propagation. A permanent response ends retrying but does not erase an earlier uncertain effect.

Each returned reply uses try-with-resources and closes exactly once before sleeping, another call or a normal return. Retry eligibility preserves the existing policy: eligible transient/unknown responses may retry under the supplied replay contract. The delay is max(localWaitNanos, serverMinimumNanos), without additional jitter. Counts, cancellation, thread interruption and a fresh remaining budget gate admission before any retry token. Subtraction-based checks avoid overflow while reserving a full next attempt plus reserve. After sleep, the loop checks again, including oversleep and cancellation. Granted tokens remain spent when cancellation or oversleep prevents a later call.

These include all three-response combinations from PENDING and UNKNOWN; stable identity/receipt; terminal snapshots; close ordering; minimum delays; exhaustion; budget rejection; exact-fit and overflowing arithmetic; elapsed call time; oversleep; cancellation at multiple boundaries; pre-interruption and exceptions during dispatch/sleep.
- `node run.mjs Smoke`: passed.
- Both commands compiled all output Java sources with `javac --release 17 -d classes ...`, then ran the selected main with assertions. The inspected runner enforced a 20-second limit per Java subprocess.
- SHA-256 comparisons confirmed the seven protected output copies remain identical to input/project.
- Bounded version probes reported Temurin JDK/javac 25.0.3 and Node v25.6.1.

The supplied Contract.REPLAY_SAFE is true. Its false branch is guarded in source but was not executed; the immutable contract was not modified to simulate another provider. No framework, database/isolation implementation or real endpoint/API version is supplied. Store durability/atomicity, peer replay retention, original-receipt recovery, physical cancellation and network timeout coverage remain contract assumptions. The tests simulate time and in-memory state; they do not prove production persistence, concurrency, wall-clock bounds or fleet behavior.
