# RetryEngine repair

The supplied contract permits retries after known non-application but prohibits redispatch of an unresolved effect when `Contract.REPLAY_SAFE=false`. The original implementation created a new intent ID per attempt, converted ambiguity to rejection, ignored initial terminal/unknown state and deadline/cancellation admission, used the smaller delay, and held each response through sleep. It also admitted an unnecessary retry after the last allowed attempt.

The repaired runner preserves the original intent and payload, returns terminal snapshots without calls, and records UNKNOWN before releasing the response or scheduling subsequent work. Only authoritative OK applies a receipt. Later permanent refusal, budget denial, exhaustion, deadline refusal and cancellation retain earlier uncertainty. A dispatch-time InterruptedException records UNKNOWN before propagation; interruption during sleep propagates after the previous reply has closed. Pre-interrupted execution starts no call.

Admission compares and subtracts the attempt allowance, reserve and delay, avoiding signed-long addition overflow. It uses the greater of the supplied local delay and server minimum for every retryable reply kind. Impossible waits stop before token acquisition. Retries consume one admission token and recheck remaining budget, cancellation and interruption after sleeping. Successful tokens are not refunded after oversleep. Every returned response closes exactly once before sleep, another call or normal return. No extra jitter was introduced because the supplied local delay already includes the chosen policy.

## Executed validation

- `node run.mjs Verification`: passed. The runner compiled with `javac --release 17`, then executed the actual implementation with assertions enabled. The supplied false replay contract passed 337 assertions.
- The same Verification process used the JDK compiler in-process to compile the actual RetryEngine source and test harness against an in-memory true replay contract, into isolated local classes. That conditional-contract suite passed 552 assertions. The supplied Contract.java was never modified.
- `node run.mjs Smoke`: passed.
- Version probes reported Temurin/OpenJDK and javac 25.0.3. Both external Java tools had a 20-second timeout.
- SHA-256 comparisons confirmed all seven immutable supplied output copies remain identical to their input counterparts.

Regression scenarios cover stable intent/receipt, initial terminal and unknown states, transient recovery, permanent failure, unsafe ambiguity refusal, permitted replay resolving prior uncertainty, later rejection/exhaustion preserving uncertainty, exact-fit and impossible budgets, overflow boundaries, server/local minima, token denial, oversleep, cancellation, dispatch interruption, sleep interruption and response ownership.

## Integration limits

This is an authored, single-owner synchronous simulation. Store durability/atomicity and peer replay semantics are supplied contracts, not experimentally established properties. No database/isolation, framework, endpoint, account namespace, key-retention window or provider API version was supplied or inferred. No reconciliation port exists; unresolved unsafe effects remain UNKNOWN and require an external recovery decision.

The test-only true contract checks conditional runner logic; it does not establish replay safety for the supplied false peer or any production provider. Logical clock checks do not measure wall-clock latency, server work termination, physical cancellation, concurrency, crash recovery or fleet amplification. Those require authorized integration evidence. Broader skill routes concerning database consistency, transport semantics and operational recovery lie outside the supplied context and were not opened. No network, global skills, repository catalog, other sessions or real agent configuration were used.
