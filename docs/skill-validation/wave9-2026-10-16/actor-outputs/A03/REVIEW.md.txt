# Retry engine repair

The supplied runner changed the intent ID, ignored initial terminal/unknown state, admitted calls without checking the deadline or cancellation, selected the smaller delay, and retained replies during sleep. It also converted ambiguous outcomes into rejection.

The repair preserves the original intent and payload, returns existing terminal snapshots unchanged, and persists observed uncertainty before any further admission. Only authoritative OK stores APPLIED and its actual receipt. A permanent response or normal admission stop stores REJECTED only when the intent has no unresolved dispatch. With the supplied immutable `Contract.REPLAY_SAFE=false`, either initial or newly observed UNKNOWN stops automatic dispatch; no reconciliation port is available.

Calls require the full configured attempt timeout plus reserve. Retry waits use `max(localWaitNanos, serverMinimumNanos)`, without drawing additional jitter. Subtraction guarded by comparisons prevents overflow. Retry admission checks outcome, count, remaining time, cancellation and a token; tokens are not refunded when cancellation or oversleep prevents the next call. The loop checks deadline and cancellation again after sleep. Replies close exactly once before admission, sleeping or normal return. Pre-interruption prevents a new call, interruption propagates, and an interrupted call first persists UNKNOWN.

Validation used the actual output implementation through the inspected runner. The first `node run.mjs Verification` failed against the original code on the changed intent ID. After repair, the same command passed 298 assertions; `node run.mjs Smoke` also passed. Both runner invocations compile with `javac --release 17` and execute with assertions enabled; each Java subprocess has a 20-second timeout. Available compiler/runtime: Temurin OpenJDK 25.0.3+9.

The regression covers successful transient retries, original receipt, both delay orderings and zero delay, terminal snapshots, unsafe UNKNOWN, exhaustion, token denial, exact-fit and overflowing durations, elapsed attempt time, oversleep, cancellation before/after admission or sleep, and interruption before dispatch, during the call and during sleep. Immutable output copies were hash-compared with their supplied input originals and matched.

These are authored simulation inputs. Store durability/atomicity and single ownership are supplied assumptions, not established by the in-memory fixture. The true replay-safe configuration was not executed because Contract.java is immutable and false. No database/isolation, HTTP endpoint/version, key namespace/retention, physical cancellation, crash durability, hidden transport retries or fleet behavior was tested. Stable identity alone supplies no provider guarantee; unresolved effects require external reconciliation. Skills that route to other packages were not followed beyond the supplied snapshots, in accordance with the task. No network or real configuration was used.
