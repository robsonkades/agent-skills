# RetryPlan repair

The repair preserves `RetryPlan.next` and `Plan`, Java 17 compatibility, and the fixed scheduling policy in `contract.md`. Only the authorized implementation was changed; `Verification.java` and reporting artifacts were added.

## Findings and decisions

The original code admitted a call when `completed == maxAttempts`, doubled the first retry's jitter window, allowed signed overflow and masked shifts in exponential growth, selected the smaller of server advice and the local draw, compared an overflow-prone sum, and allocated attempt time without deducting wait and reserve.

The repaired planner rejects when `completed >= maxAttempts`. It computes elapsed time as `now - start`, which supports negative readings and signed wrap under the contract's elapsed duration below 2^63 nanoseconds. The former `start + total - now` also has the correct modular result within that contract; the elapsed form makes the assumption explicit rather than claiming a separate demonstrated defect there.

Budget arithmetic subtracts only after comparisons establish nonnegative values. After checking expiry and reserve, `available = total - elapsed - reserve`. It rejects when `available < minimumWork`. On retries, `maximumWait = available - minimumWork` safely detects server advice that cannot fit without adding large durations. The initial call ignores server advice and never invokes the draw.

For retries, the exponent is `completed - 1`. Before shifting, the implementation checks both `exponent >= 63` and whether the multiplication would exceed `Long.MAX_VALUE`; saturation followed by the delay cap computes the exact mathematical window. The supplied draw receives that positive half-open bound. The selected wait is exactly `max(draw, serverMinimum)`, without extra jitter or truncating server advice. A wait above `maximumWait` rejects; otherwise the attempt is exactly `min(attemptCap, available - wait)`. Equality admits. Rejections have both durations zero. No narrower input limit or arbitrary duration cap was introduced.

## Validation executed

`node run.mjs Verification` compiled all three Java files with `javac --release 17 -d classes` and ran `java -ea -cp classes Verification`: **112,350 plans checked**, exit 0. Named cases and a deterministic matrix exercise the actual implementation against an independent `BigInteger` arithmetic oracle. They cover attempt limits, first-call behavior, exact fits, one-nanosecond shortages, maximum durations/reserves/advice, negative and wrapped clock readings, delay caps, shift boundaries and very large attempt counts. Draws at zero, midpoint and upper bound minus one check the full allowed window; this is not a statistical randomness test.

`node run.mjs Smoke` compiled the same files and printed `Smoke passed`, exit 0. Runtime checks reported Temurin OpenJDK 25.0.3+9 and javac 25.0.3. The inspected runner sets a 20-second timeout per Java subprocess. SHA-256 comparisons confirmed `README.md`, `REQUEST.md`, `contract.md`, `Smoke.java` and `run.mjs` unchanged.

## Boundary and limitations

This pure planner enforces arithmetic admission at the supplied `now`; it neither sleeps nor dispatches, cancels work, releases resources, interprets failure evidence, validates raw server headers, or enforces a fleet retry budget. Callers must recheck the remaining budget after actual waiting and intervening work, apply the per-attempt bound, coordinate hidden retries, and own cancellation. Scheduling and cleanup can overrun a planned duration.

Admission does not establish that a remote effect is safe to repeat. Callers need operation-specific replay safety or authoritative reconciliation, preserve unresolved prior outcomes, and reproduce the same intent. No provider, database, client or framework contract is supplied or tested here; local arithmetic checks establish no durable remote guarantee, production wall-clock bound, cancellation behavior, fleet amplification or randomness quality.

Only supplied skills and relevant local retry/deadline arithmetic references were used. Routes to other skills and external primary sources were not followed because this exercise forbids browsing and broader skill context. The endpoint/key and client-configuration references are outside this planner's scope. No network workload, repository-wide verification, installation or real configuration change was performed.
