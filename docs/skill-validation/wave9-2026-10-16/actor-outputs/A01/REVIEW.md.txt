# RetryEngine repair

The supplied implementation changed the operation ID on every call, ignored the initial durable state and remaining deadline, used the smaller delay, leaked responses on several exits, and converted uncertain effects into rejection. The repair preserves the public signature and Java 17 baseline.

The same intent and payload now reach every permitted call. Existing APPLIED/REJECTED snapshots return unchanged with zero attempts. UNKNOWN is persisted when observed and when dispatch throws InterruptedException. Normal stops preserve UNKNOWN unless an authoritative OK supplies the receipt; known non-application stops persist REJECTED. Contract.REPLAY_SAFE is false in this exercise, so initial or observed uncertainty stops automatic dispatch and remains a recovery obligation.

Before dispatch, the engine requires the full attempt timeout plus reserve. Before retry admission, it requires max(local delay, server minimum), another full attempt and reserve. Comparisons and subtraction avoid signed-long overflow. Unfittable waits are refused without truncation or token consumption. Each admitted retry consumes one token; fresh checks before sleep and after sleep prevent dispatch after cancellation or oversleep. Max attempts counts calls in this invocation, including the first token-free call. Pre-interruption prevents dispatch; dispatch and sleep interruptions propagate.

Try-with-resources closes every returned reply once before sleeping, another call, or a normal return. No new jitter, delay policy, provider guarantee, or receipt was introduced.

Validation executed against the delivered source:

- node run.mjs Verification: 26 scenarios passed, with javac --release 17 and Java assertions enabled.
- node run.mjs Smoke: Smoke passed.
- The same Verification compiled with the immutable original RetryEngine failed as expected: it dispatched a terminal snapshot and changed the intent ID.
- java -version and javac -version reported Temurin/OpenJDK 25.0.3.
- SHA-256 comparisons confirmed that all seven immutable supplied copies remained identical to their inputs.

The regression covers terminal replay, stable identity and timeout, both delay priorities, zero delay, exhaustion, prior and observed uncertainty, repeated invocations, permanent rejection, exact/insufficient budgets, overflow boundaries, elapsed call time, token denial, oversleep, cancellation before/after admission and sleep, pre-interruption, and dispatch/sleep interruption. Response-close assertions run before admissions, sleeps, later calls and normal results.

This is a deterministic single-owner component simulation. The supplied store's durability and atomicity are assumed; no database, isolation level, HTTP endpoint, SDK, API version, tenant namespace, fingerprint enforcement or retention window is provided. Those boundaries were not implemented or validated. REPLAY_SAFE=true cannot be exercised without changing the immutable contract; its branch received source inspection only. There is no reconciliation port, so unresolved outcomes require integration-level recovery. The tests establish neither remote cancellation nor wall-clock or fleet behavior. Referenced skills outside the two supplied snapshots were not opened; concurrency, provider recovery, storage and transport work remain outside this assignment.
