The repaired `RetryEngine.execute` retains its public signature and Java 17 baseline. The original implementation changed the intent ID on every call, overwrote unresolved outcomes with rejection, skipped deadline/cancellation admission, chose the smaller delay, and held replies open during backoff.

The engine now sends the original immutable intent and exact configured attempt timeout. Previously terminal snapshots return unchanged with zero attempts. Initial or observed UNKNOWN remains unresolved across transient/permanent replies, exhausted attempts, time refusal, cancellation and denied retry admission. Only an authoritative OK supplies the receipt and transitions to APPLIED. An interruption from the operation records UNKNOWN before propagating; sleep and pre-interruption propagate without starting another call. With no uncertainty, normal refusal/exhaustion persists REJECTED, as this exercise explicitly requires.

Each returned reply is closed once before persistence-driven continuation, sleep, another call or normal return. Retry admission uses `max(localWaitNanos, serverMinimumNanos)` and compares by subtraction, avoiding overflow when valid long durations cannot fit together. A wait must leave the entire next attempt and reserve. The initial call uses no retry token; eligible retries request one token only after count, cancellation and time checks. Expiry, interruption and cancellation are checked again after sleep, so oversleep can consume a granted token without causing another call. The supplied local delay is retained without introducing another jitter draw.
