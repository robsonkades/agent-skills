# Revisão do relato de totais após recarga

## Conclusão

A sequência relatada está de acordo com o contrato aceito. Não foi identificado defeito no fluxo `Catalog.load()` → `Catalog.open()` → `Report.total()`. A mudança de 1000 para 1200 é a atualização exigida para um relatório vivo após uma recarga; os artefatos locais não demonstram uma regressão de arredondamento.

O código de produção foi preservado. Fazer uma cópia dos itens ou guardar o total inicial impediria a atualização dos relatórios abertos e violaria o contrato.

## Evidências e causa

- `project/contract.md` exige uma visão viva e somente leitura, inclusive para entradas e total de relatórios abertos antes de uma chamada posterior a `load()`. A execução é sequencial.
- `project/src/work/Catalog.java` mantém uma única lista `rows`; `load()` altera essa lista com `clear()` e `addAll()`. `open()` entrega uma visão `Collections.unmodifiableList(rows)`, que bloqueia alterações pelo consumidor e acompanha alterações feitas pelo catálogo.
- `project/src/work/Report.java` recalcula o total das entradas atuais com `mapToLong(Entry::cents).sum()`. Não há ponto flutuante nem operação de arredondamento nesse caminho. `Entry` é um `record` composto por `String` e `long`, valores imutáveis neste modelo.
- O `Demo` primeiro carrega 450 + 550, abre o relatório e depois substitui as entradas por uma de 1200. Tanto antes quanto depois da ampliação dos testes, sua saída foi exatamente:

```text
first=1000
first-after-reload=1200
latest=1200
```

O diagnóstico do chamado confunde atualização dos dados com arredondamento. Não há renderer nem histórico da alteração mencionada nos arquivos fornecidos para atribuir causa a uma versão anterior.

## Alterações

Somente `project/test/work/SelfTest.java` foi alterado dentro do projeto. Foram mantidas as verificações originais de total/tamanho inicial e rejeição de `clear()`. Foram acrescentadas verificações comportamentais de:

- recargas observáveis por relatórios já abertos e pela lista de entradas previamente obtida;
- consistência entre relatórios antigos e novos, inclusive após múltiplas recargas;
- preservação de ordem, duplicatas e centavos negativos;
- rejeição de adição, remoção, substituição, ordenação e remoção via sublista;
- preservação dos dados após tentativas de alteração;
- recarga vazia e uma nova recarga após esvaziar o catálogo.

Fontes de produção, contrato, configuração, dependências, entradas originais e baseline Java foram preservados. `verify.mjs`, `finalize.mjs`, `logs/` e `execution.json` documentam a execução e ficam fora de `project/`.

## Verificação executada

No diretório deste run, o script `node output/verify.mjs baseline` executou a verificação original antes de qualquer mudança no teste. `node output/verify.mjs final` executou a mesma verificação depois da ampliação. Ambos foram lançados com um supervisor `spawnSync` com limite de 30 segundos; os comandos completos estão em `execution.json`.

Em cada fase, o script executou `java.exe -version`, `node check.mjs` e `java.exe -cp .build work.Demo`, todos com limite de 30 segundos. O `check.mjs` original compila fontes e testes com `javac.exe --release 17 -d .build ...` e executa `work.SelfTest`, também com limites de 30 segundos. Resultados: saída `SelfTest PASS`, sequência do `Demo` acima e código de saída 0 em todos os comandos.

Runtime confirmado: Temurin **25.0.3+9**, preservado. O alvo de compilação continua **Java 17**. Logs completos estão em `logs/baseline-*.json` e `logs/final-*.json`; conteúdos lidos, hashes e a comparação dos arquivos finais estão em `execution.json`.

## Limitações e escopo

Esta conclusão cobre os artefatos locais e o contrato sequencial fornecido. Não houve acesso a produção, banco de dados, outros aplicativos, rede, instalações, configuração real ou agentes auxiliares. O bytecode foi compilado para Java 17 e executado no runtime disponível Java 25; não foi usado um runtime Java 17 separado.

Na primeira leitura de `TASK.md`, o processo herdou `C:/git/agent-skills` como diretório de trabalho. O comando leu somente o caminho absoluto de `TASK.md` deste run: nenhum conteúdo do repositório foi consultado ou escrito. Todos os comandos seguintes usaram o diretório autorizado deste run. Nenhuma skill ou referência externa foi lida. Todas as escritas foram limitadas a `output/`.
