Call BookingService through the configured Spring application context. The schema is initialized by the existing launcher/tests. Inspect booking, receipt and stock state outside the completed command. Document the selected failure behavior here if it changes.

BookingService.place still uses REQUIRED participation in businessTx: an existing caller owns
the booking/reservation transaction. Receipt dispatch is synchronous AFTER_COMMIT, with the
default fallbackExecution=false. The separately proxied ReceiptWriter uses REQUIRES_NEW on
businessTx so its header and detail are one independent transaction after source commit.

A rejected body (more than 12 characters) rolls back both receipt writes. Spring 7.0.9's
transactional event AFTER_COMMIT phase runs through afterCompletion; its exception handling
logs the failure without propagating it to the successful business caller. The booking and
stock reservation remain committed. The observer still executes inside the writer immediately
before the header insert. Do not catch the write failure inside the writer and commit its header.

Run `node check.mjs` and `node check.mjs work.Regression`. The regression reads persisted
state through independent READ_COMMITTED connections, including from ReceiptObserver, and
covers valid/invalid bodies, absent stock, nontransactional events, owner commit/rollback and
a later beforeCommit owner failure. REQUIRES_NEW alone with BEFORE_COMMIT fails these checks
and can leave an orphan receipt after the owner rolls back.

Receipt loss on write failure or interruption is accepted; there is no recovery store or retry.
These in-memory H2 checks do not establish production crash durability, JPA behavior,
distributed delivery, or deduplication guarantees.
