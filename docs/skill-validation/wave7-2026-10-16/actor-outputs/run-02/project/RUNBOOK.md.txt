Call BookingService through the configured Spring application context. The schema is initialized by the existing launcher/tests. Inspect booking, receipt, receipt_detail and stock state outside the completed command.

The existing businessTx boundary uses REQUIRED. BookingListener runs BEFORE_COMMIT, and ReceiptWriter uses the same transaction-bound JdbcTemplate connection. Its diagnostic observer remains immediately before the header/body writes and can see the publisher's uncommitted booking. Keep this local atomic unit: no independent receipt transaction is required.

A valid receipt of at most 12 characters commits with the booking and stock decrement. A longer body fails completion and rolls back the header, booking and decrement as well as the body. Unavailable stock fails the call and leaves none of that operation's changes. A publication made without an active transaction is deliberately ignored; it is not a receipt recovery operation.

An existing transaction's caller owns completion. Returning from place inside that transaction does not mean the booking has committed or its receipt callback has run. A subsequent owner failure rolls back the unit; even a completion failure after both receipt writes leaves no partial receipt. Let failures reach the completion owner instead of retrying receipt writes independently.

Run `node check.mjs` for the original smoke check and `node check.mjs work.Regression` for seven persisted-state regressions using the actual Spring beans. Then `node ../checks/blanket-requires-new.mjs` compiles a separate negative control outside src: the regression must reject an independent writer because it cannot see the uncommitted booking. The control's failed JVM is expected and its complete output is retained under ../checks/requires-new-results.json.

These are local H2/JDBC checks with Java 25 and Framework 7.0.9. They do not establish production-engine crash durability, distributed deduplication, recovery guarantees or JPA behavior. The supplied call path is the scope: the writer is a collaborator invoked by the transaction-bound listener, not a standalone booking operation.
