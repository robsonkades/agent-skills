# Accepted contract and available provider specification
Readers may return -1 when no snapshot is available. A present snapshot must have value 91. Each provider instance issues one callback. Provider contract guarantees only non-null Snapshot and callback-at-most-once; it documents no cross-thread publication or memory consistency effect. Its log says value assignment happened earlier in wall-clock time, but no trace of thread identity or handoff is available. Snapshot's API permits setValue before handing it to the callback, with no later mutations. No guarantee about synchronization from the producer to the callback thread is supplied. Treat this as an unresolved integration contract, not permission to invent provider behavior.
