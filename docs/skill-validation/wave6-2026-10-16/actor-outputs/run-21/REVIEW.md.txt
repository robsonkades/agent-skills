The accepted lookup contract is satisfied. Preserve the production code; no correction is required. The conclusion assumes the explicitly accepted single installation of `42`, private construction, handoff before `Thread.start()`, and absence of later mutation or constructor escape.

The effective path is `BestEffortMemo.find()` (lines 9–11) → `reader.applyAsInt(observed)` → `ReaderFactory.create()` returning `PublishedEntry::value` (line 5) → `PublishedEntry.value()` reading `primary.value` (line 11). `find()` reads `entry` once into a local and checks that same reference for null. The unused `legacyValue()` is a different path and does not establish a defect in this lookup.

The memo and reader are initialized before each participating thread starts, so their initial state is ordered into those threads. This start edge does not order a producer's later installation with independent consumer reads. `entry` therefore has a data race. Atomic reference access selects null or the installed entry; null yields an accepted miss, potentially indefinitely. These are separate guarantees. [JLS 17.4.5](https://docs.oracle.com/javase/specs/jls/se25/html/jls-17.html#jls-17.4.5), [JLS 17.7](https://docs.oracle.com/javase/specs/jls/se25/html/jls-17.html#jls-17.7).

For a hit, the relevant producer actions are `payload.value = 42` → `primary = payload` → constructor exit/freeze → `entry = constructedEntry`. The consumer obtains that entry, reads final `primary`, then dereferences its payload. With no escape or subsequent mutation, final-field semantics protect both the initialized `primary` reference and the payload state reached through it. The payload's `value` need not itself be final for these construction-time writes to be covered. Thus this path reads `42`, not zero or a null primary. This is a freeze/dereference guarantee, not a generic publication happens-before edge. [JLS 17.5–17.5.1](https://docs.oracle.com/javase/specs/jls/se25/html/jls-17.html#jls-17.5.1).

The factory selects `value()`, and the compiled method-reference bootstrap also targets `PublishedEntry.value`. There is no lookup access to `legacy`. Requiring volatile publication or changing every payload field would impose an unnecessary correction on this accepted behavior.
