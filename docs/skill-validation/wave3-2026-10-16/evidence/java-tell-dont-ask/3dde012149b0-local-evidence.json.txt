(The first edition is the one that had the influence, the second edition is good but you'll need several months in a gym before you can lift it.)\nL75: The fundamental idea is that we should divide an object's methods into two sharply separated categories:\nL76: \nL77:   * Queries: Return a result and do not change the observable state of the system (are free of side effects).\nL78:   * Commands: Change the state of a system but do not return a value.\nL79: \nL80: Because the term 'command' is widely used in other contexts I prefer to refer to them as 'modifiers', you also see the term 'mutators'.\nL81: The really valuable idea in this principle is that it's extremely handy if you can clearly separate methods that change state from those that don't. You have to be more careful with modifiers.\nL82: The notion in the principle is that the return type is the give-away for the difference. It's a good convention because most of the time it works well. Personally I'd much prefer a style that has separate `advance` and `current` methods.\nL83: Meyer likes to use command-query separation absolutely, but there are exceptions.
