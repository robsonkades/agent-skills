# Experiment context
This is a complete, synthetic fixed-run fixture, not a production capture.
Runtime selection: grpc-java 1.84.0 with Netty; Envoy 1.36.0.
The same read-only unary ReadSnapshot method was called ten times per variant.
A useful result is exactly one valid Snapshot delivered to the consumer and an OK terminal call outcome.
Gate for this fixed run: at least 95% useful results and successful-call p95 no greater than 80 ms.
Every onMessage payload passed schema/content validation; one row records one logical call.
client_callbacks.csv records the client's onMessage count and numeric status code at onClose.
proxy_calls.csv records the correlated Envoy downstream HTTP exchange.
There were no retries or hedges, no unobserved calls and no sampling.
The log format includes HTTP response code and duration, but no gRPC status field.
Both runs used one reused channel/connection; event-loop utilization stayed below 20%.
Effective configuration and matched security/placement/payload evidence were checked before this export.
The saved query is PostgreSQL-style SQL shown for inspection; no database is required to examine the CSV fixtures.
