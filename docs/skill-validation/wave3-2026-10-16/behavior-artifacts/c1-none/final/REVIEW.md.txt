# Review result

Corrected `decision.md` and changed the sole necessary policy field:
`connect_start: first_client_data` became `connect_start: immediate`.
The listener, trusted fixed route, 1000 ms inspection timeout, and 4096-byte
inspection buffer limit remain unchanged. Implementation fixtures remain intact.

The original proposal inferred application compatibility from downstream TCP
acceptance and proposed a longer inspection timeout as a handshake repair.
Neither conclusion follows from the supplied evidence. The protocol is
server-first: the client waits for `HELLO`, but the deferred adapter waits for
client bytes before connecting the server that emits `HELLO`. Immediate upstream
connection breaks that circular wait because the route needs no client payload.
A longer timeout does not create the missing first message.

# Coverage and limits

The probe executes the actual supplied client/server handshake and models the
documented upstream connection trigger. It is not the actual installed adapter,
and it is not vendor configuration. The test's 1200 ms deadline is independent
of the policy's 1000 ms inspection bound. The contract does not specify the
adapter's timeout action; this model does not invent or validate that action.
The model applies the buffer limit to queued bytes, but overflow behavior was not
tested. Nothing here validates overload, arbitrary framing or payloads, failures
after connection, real route resolution, real adapter/version configuration, TLS,
authentication, or deployment behavior. Full handshake validation against the
actual implementation remains necessary before operational reliance.

No tools were installed; no deployments, vendor configuration conversion, TLS or
authentication edits, retries, or external network lookups were performed.
