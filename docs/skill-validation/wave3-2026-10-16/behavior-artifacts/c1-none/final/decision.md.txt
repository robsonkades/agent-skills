# Proposal

Change only `connect_start` in `proxy-policy.json` from `first_client_data` to
`immediate`. Keep the listener `127.0.0.1:15001`, trusted fixed route
`fixed-service-a`, inspection timeout of 1000 ms, and buffer limit of 4096 bytes.
These choices remain adequate for the supplied fixture; no broader capacity or
deployment claim is established.

`protocol.json` selects a server-first exchange. `attachServer` sends `HELLO\n`
when attached to an upstream connection. `attachClient` waits for that greeting
before sending `PING\n`; receipt of `PONG\n` completes the exchange. Under the
adapter contract, `first_client_data` opens no upstream connection until the
client sends bytes. Thus the client waits for the server, while the adapter waits
for the client and prevents the server from sending its greeting.

A successful downstream TCP connection establishes listener reachability only.
It does not establish an upstream connection or completion of this application
handshake. Increasing the inspection timeout to ten seconds cannot remove the
circular wait. Keep its existing bound and fix the connection trigger.

The route is trusted, fixed, and known without parsing client data, so opening
upstream immediately on downstream acceptance is justified. The resulting flow
is downstream acceptance, upstream connection, server `HELLO`, client `PING`,
then server `PONG`. Keep TLS, authentication, and the absence of retries unchanged.

## Local evidence and remaining validation

`node .\local-handshake-check.mjs` ran with Node v25.6.1. It uses the supplied
client and server, ephemeral loopback ports, and a small model of the documented
adapter connection gate. The direct control completed the exchange in 15 ms;
the proposed immediate gate completed it in 3 ms. The original deferred gate
accepted downstream TCP but made zero upstream attempts and exchanged no
application bytes before the 1200 ms observation deadline (1204 ms measured).
All assertions passed and all listeners closed. Logs are retained in
`local-handshake-check.log`.

The observation deadline belongs to the test, not an asserted adapter inspection
timeout action. The supplied contract does not specify that action. This check
does not validate a real proxy implementation, deployed configuration, timeout
or overload behavior, TLS, or authentication. This remains a fixture design
proposal, not runnable Envoy or other vendor configuration. Before relying on a
real implementation, verify its exact adapter/version mapping and repeat the
bounded server-first handshake against that implementation in an isolated
environment. No deployment was performed.
