# Invoice export review

Approve the exact proposal for semantics; keep `solution.sql` byte-for-byte equal to `proposed.sql`. No repair or schema change is needed. Performance approval is unsupported by the supplied evidence.

Let `p` mean `active = true` and `q` mean `amount >= 100`. The schema declares `active boolean NOT NULL CHECK(active IN (false,true))`, so `p` is always true or false for an allowed row. The branches partition qualifying invoices:

| p | q | Original emits | First branch | Second branch |
| --- | --- | --- | --- | --- |
| true | false | 1 | 1 | 0 |
| true | true | 1 | 1 | 0 |
| false | false | 0 | 0 | 0 |
| false | true | 1 | 0 | 1 |

Thus the overlap is emitted once. `NOT p` is safe here because `p` cannot be unknown; a nullable-active counterexample is outside this schema. The partition argument does not depend on a finite sampling of amounts. [PostgreSQL 17 logical operators](https://www.postgresql.org/docs/17/functions-logical.html).

Both branches retain `tenant_id = :tenant`, project only `customer_label`, and the final `ORDER BY customer_label` orders the combined result. `UNION ALL` preserves separate invoices having identical labels, while plain `UNION` would wrongly collapse them. The supplied tenant 71 result is `Acme, Acme, Bravo`. [PostgreSQL 17 set operations](https://www.postgresql.org/docs/17/queries-union.html).

Run `node verify.mjs` from this directory. It reads the actual `solution.sql` and the supplied helper, then compares ordered arrays against both explicit seed expectations and an independent generated-row oracle. Each successful run checks 11 cases, including 124 generated invoices across four tenants, both legal active values, amounts below/equal/above 100 and numeric extremes, repeated labels, predicate overlap, ordering, projection, empty results and a null tenant parameter. Separate checks confirm rejection of NULL and 2 for active. The original files and copied artifacts remain byte-identical.

The candidate passed before and after mutation testing on Node v25.6.1 / SQLite 3.51.2. `node check-mutants.mjs` temporarily replaces `solution.sql`, runs the same regression, and restores the original bytes in `finally`. All five wrong variants failed: overlapping rows duplicated, labels deduplicated, second-branch tenant leakage, excluded threshold equality, and reversed order. See `verification-run.json` for actual exits and output.

Two indexable branches do not establish a speedup. PostgreSQL can already combine indexes for OR; the rewrite may introduce extra scans, overlap filtering, heap visits and sorting. A sequential scan can also be appropriate for a large qualifying fraction. These are hypotheses, not observed plans. [PostgreSQL 17 combining indexes](https://www.postgresql.org/docs/17/indexes-bitmap-scans.html).
