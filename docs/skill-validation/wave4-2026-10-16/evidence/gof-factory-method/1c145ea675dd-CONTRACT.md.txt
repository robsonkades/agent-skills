# Import adapter contract

Java source/API baseline: 17, no dependencies or preview features.
Review the installation selected by binding.properties. Keep that configured ownership
and allocation policy. The dormant alternative binding illustrates other deployments;
report it separately if relevant rather than treating its lifetime as the active one.

ImportJob is a published subclass extension point. Its final run method gets one owned
parser or operation-scoped lease from the protected factory hook, then performs synchronous
parse/save and closes the returned object. Keep that signature, IOException propagation,
one factory invocation per run, and cleanup even on processing failure.

ApplicationBinding is application-owned and closes at application shutdown. Its factory
can supply either an application-owned parser or transfer a per-operation parser, as stated
by its active scope. Adapters must honor both the actual binding lifetime and the inherited
hook's consumer contract. A createParser name is not an additional lifecycle guarantee.

The configured application must support two sequential successful imports and still release
each resource at its declared owner boundary. No concurrent workload, lazy caching, external
plugin removal, remote I/O or database transaction is part of this review.
