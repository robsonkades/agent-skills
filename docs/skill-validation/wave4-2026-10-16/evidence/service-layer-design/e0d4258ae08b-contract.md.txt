# Submission boundary

Authored case fixture. These are partial source excerpts, not a compiled application.
Use the declared Java17/Spring6.2.12 semantics without an upgrade. Imported application
types, injection and controller wiring are omitted.

SubmissionService is a Spring-managed imperative transactional proxy. REQUIRED is the
effective propagation. Endpoint and Entry are not transaction-advised. The configured
outer TransactionTemplate, when enabled, uses the same transaction manager/resources.
The entry property is effective runtime configuration for this case, not an annotation
whose activation still needs guessing.

COMMITTED means this submission's accepted local database transaction completed
successfully before the receipt is emitted. UNKNOWN means completion certainty is
unavailable. An authoritative business rejection uses its separate established outcome.
This task does not promise exactly-once receipt delivery or atomic database/network
publication. There is one receipt emitter, replies.accept, and it is external to the
database transaction. Do not invent removal of that effect or a propagation-policy change.

Actor authorization and tenant scope have already been enforced in a shared entry policy
used by both paths; those controls remain. Submission identity and prior accepted business
decisions must survive any correction. The local domain rules remain with the existing
aggregate. The runtime failure is specified in failure-plan.json, not observed here.
