# Capture protocol

App owns the driver, completion-delivery object and view for its lifetime. All calls in this
fixture run on one application thread; there is no concurrent request thread or background I/O.
The selected delivery implementation is part of this deployment's supported contract.

A first request starts one capture. If the driver reports captured, the view is updated once
and the coordinator must remain DONE after the call stack and pending delivery have finished.
Further requests in RUNNING, DONE or UNKNOWN do not start another capture.

The driver can also throw without a terminal outcome. The protocol then records UNKNOWN and
preserves that outcome; the caller receives the original failure. Automatic retry is not allowed.
The fixture does not promise cancellation, restart recovery, multiple operation generations or
physical-device idempotency. Driver/view ownership is unchanged by the review.
