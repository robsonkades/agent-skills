# Account concurrency test review

Corrected `test/AccountTest.java` against `docs/account-contract.md`. Production source,
Java 21 target, dependency versions and the supplied runner are unchanged.

The original conservation/accounting assertions admitted an implementation that always
returned `false`. The repeated test now requires exactly 1,000 successful withdrawals,
31,000 insufficient-funds refusals and a zero final balance. These totals follow from
32,000 attempts of 10 against 10,000, without deposits, fees or permitted busy refusals.
All existing assertions, 20 repetitions, worker Future observations and cleanup remain.

The added test holds the supplied gate before starting an affordable withdrawal. A
start latch alone does not establish contention: it therefore polls until that specific
worker is waiting at the fixture's only subsequent blocking operation, or its Future
completes. It releases the gate and requires `true`, exactly one subtraction, and a
subsequent insufficient-funds refusal with no balance change. It observes both worker
results. The poll's 1 ms delay is pacing; the observed checkpoint is the oracle.

Latch/poll/result waits are bounded at two seconds. Cleanup independently releases
the holder, cancels retained Futures, shuts down the executor, and awaits termination
for two seconds. Grouped assertions preserve ordinary worker and teardown failures.
The new test has a 10-second JUnit timeout; the existing stress test retains its
30-second timeout, 5-second barrier and shared 20-second result budget. The holder's
existing 5-second bound and runner's 60-second process deadlines remain unchanged.
