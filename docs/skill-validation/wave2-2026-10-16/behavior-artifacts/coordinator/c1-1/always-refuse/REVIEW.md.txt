# Account concurrency test review

Corrected `test/AccountTest.java` using `docs/account-contract.md`. Production source,
Java 21 compiler target (no preview), JUnit Jupiter 5.11.4 dependencies, and the
existing bounded worker/cleanup structure are unchanged.

The original conservation/accounting assertions admitted an implementation that
always returned false. The repeated test now also requires 1,000 successes,
31,000 refusals, and zero final balance: all 32,000 calls withdraw 10 from an
initial 10,000, and this fixture has no deposits or fees. Existing nonnegative,
conservation, accounting, worker-result, and termination checks remain.

The added test acquires `holdGate` before starting an affordable withdrawal. It
rejects an observed false result while the gate is held, then releases the gate,
requires true, observes the gate-owner future, and requires balance 70 after
withdrawing 30 from 100. Release is also in `finally`, before cancellation and
shutdown. Latch waits and final future waits are bounded at two seconds, the
held-gate observation window is 250 ms, termination is bounded at two seconds,
and the test has a 15-second JUnit timeout. There is no unbounded executor close.

## Limits

Twenty repetitions sample schedules; they do not establish linearizability or
exhaustive concurrency coverage. The contention latch signals immediately before
`withdraw`, not from inside it. A severely delayed worker can therefore first
execute the call after gate release; the 250 ms window is a bounded observation
opportunity, not proof of overlap on every run. The observed contention mutation
failure establishes detection in this run. Timeouts bound the test harness and
can fail on a sufficiently stalled environment; they do not prove production
liveness. Java 21 compatibility was compiled, but execution used Java 25.0.3,
not a separate Java 21 runtime. Fault probes cover only the three stated defects.
