# Account test review

The existing stress test checks conservation, nonnegative balance and complete
outcome accounting after all workers finish. Those checks have a continuing
contract purpose and were preserved, including all 20 repetitions, bounded
barrier/future waits, cancellation, executor shutdown and termination assertion.

It had a specific blind spot: an implementation that always returns false
without changing the balance satisfies all three assertions (`succeeded = 0`,
`refused = 32,000`, `balance = 10,000`). The contract requires acceptance of a
positive affordable withdrawal when the gate is free.

Added `affordableWithdrawalsSucceedWhenGateIsFree` in `test/AccountTest.java`.
A fresh account used by one thread has a free gate. The test requires successful
withdrawals of 30 and 70 from an initial 100, and verifies balances of 70 and 0.
This also checks that a completed withdrawal leaves the next affordable operation
usable. No assertion requires all contending workers to succeed. The `holdGate`
hook is unnecessary for this isolated free-gate condition.

Production code, compiler target, dependency versions and the check runner were
not edited. No dependencies were installed or real agent configuration accessed.
