# Account concurrency test review

The production implementation passed the original tests, but their oracle admitted an invalid implementation that always returned `false`: nonnegative balance, conservation, and total outcome accounting would all still pass. `docs/account-contract.md` requires every positive affordable withdrawal to succeed; contention is not insufficient funds.

`test/AccountTest.java` now retains every original assertion, repetition, barrier, worker-result check, and cleanup bound. It additionally requires exactly 1,000 successes, 31,000 refusals, and a zero final balance in each stress repetition. A separate controlled test holds the existing gate, starts an affordable withdrawal, and waits for observable blocking or completion before releasing the gate. It requires success, the exact balance change, and an unchanged balance after a subsequent insufficient-funds refusal.

The gate acquisition latch establishes ownership. The startup latch alone is insufficient, so a two-second poll observes either the worker's `WAITING` state or its completed Future. After startup, this worker's only blocking operation is `withdraw`; this is a fixture-specific inference, not a general interpretation of thread state. `Thread.sleep(1)` only backs off between observations. Java documents parking as a source of [`WAITING`](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Thread.State.html#WAITING). Both Futures are checked even if coordination fails. Independent gate release runs in `finally`; cancellation, shutdown, and a separate two-second termination assertion preserve bounded cleanup and aggregate worker/cleanup failures.

## Limits and final state

A passing run means no checked invariant failed in these executions; it does not prove thread safety or exhaustive linearizability. Aggregate exhaustion alone can still miss early false refusals if later attempts consume the funds; the controlled case checks the specific contention refusal scenario. No mutation run, full operation-history checker, mixed-amount matrix, alternate JDK/provider, or Java 21 runtime run was performed. The timing bounds are harness budgets, not production guarantees. Cancellation/interruption semantics are not declared by the account contract, so no new business-level promises were invented. The local `node check.mjs` was the applicable check; parent-repository checks were outside the task scope.

All writes are stopped after this report's creation. No test process or owned worker remains running.
