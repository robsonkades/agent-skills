## Evidence and calculation

The accepted SLO requires the caller to receive the required successful result within 100 ms for at least 99% of **all 10,000 eligible logical operations** started in the fixed measured cohort. There are no excluded operations. The start-side census is complete; counts concern logical operations, not retry attempts.

The dashboard divides 9,800 timely successful terminal events by 9,800 observed terminal events and reports 100%. This denominator excludes 200 eligible operations, so it does not measure the accepted population. The collector lost their terminal records, and their timely outcomes cannot be reconstructed. They remain unknown, not known timeouts or known deadline misses.

Let `g` be the number of those 200 unknown operations that actually met the good-event definition:

```text
Known good = 9,800; known bad = 0; unknown = 200
Eligible population = 9,800 + 0 + 200 = 10,000
Actual good fraction = (9,800 + g) / 10,000, where 0 <= g <= 200
Evidence bounds = 98% to 100%, inclusive
Required good count = ceil(0.99 * 10,000) = 9,900
Required good outcomes among unknowns = 9,900 - 9,800 = 100
```

If at least 100 unknown operations were good, the SLO was met; if at most 99 were good, it was missed. Both possibilities fit the supplied records. The 98% lower bound is the guaranteed fraction, not a measured 98% service outcome. Zero known bad operations likewise does not establish that all eligible operations were good. These are deterministic bounds on a complete fixed cohort, not a statistical confidence interval.

The normal-peak capacity claim at 1,000 offered operations/s therefore remains unsupported. Establishing a PASS requires evidence of at least 9,900 timely successful outcomes for the accepted population. The provided records cannot supply that evidence because the lost outcomes cannot be reconstructed. Future evidence collection would require separate authorization; no new load test or deployment was run. A cohort-based report should retain the full eligible denominator and expose unknown outcomes separately.

### Exact arithmetic check and observed outcome

The following command completed with exit code 0 and emitted five PASS lines plus the scope statement, saved in `checks.log`. It checked reconciliation, the 9,900-good threshold, the 98%-100% bounds, the 100 additional good outcomes needed, and indeterminate compliance. It performed no workload execution.

```powershell
$slo = Get-Content -LiteralPath 'slo.json' -Raw | ConvertFrom-Json
$cohort = Get-Content -LiteralPath 'cohort.json' -Raw | ConvertFrom-Json
$requiredGood = [int][Math]::Ceiling($slo.requiredGoodFraction * $cohort.eligibleOperations)
$lowerGoodFraction = $cohort.knownGood / $cohort.eligibleOperations
$upperGoodFraction = ($cohort.knownGood + $cohort.missingTerminalRecords) / $cohort.eligibleOperations
$additionalGoodRequired = $requiredGood - $cohort.knownGood
if (($cohort.knownGood + $cohort.knownBad + $cohort.missingTerminalRecords) -ne $cohort.eligibleOperations) { throw 'Cohort counts do not reconcile.' }
if ($requiredGood -ne 9900 -or $additionalGoodRequired -ne 100) { throw 'Unexpected SLO threshold.' }
if ($lowerGoodFraction -ne 0.98 -or $upperGoodFraction -ne 1.0) { throw 'Unexpected bounds.' }
if (-not ($lowerGoodFraction -lt $slo.requiredGoodFraction -and $upperGoodFraction -ge $slo.requiredGoodFraction)) { throw 'Expected indeterminate compliance.' }
$checkLines = @(
  'PASS: cohort reconciles: 9800 known good + 0 known bad + 200 unknown = 10000 eligible logical operations.',
  'PASS: accepted SLO requires at least 9900 good operations (99%).',
  'PASS: guaranteed good fraction = 98%; possible good fraction = 100%.',
  'PASS: at least 100 of 200 unknown operations must be good to meet the SLO.',
  'PASS: both compliant and noncompliant outcomes remain possible; dashboard PASS is unsupported.',
  'No load test, deployment, dependency installation or production contact was performed.'
```
